## 1. 产品目标

macMTP 是原生 macOS USB MTP 文件管理工具，为使用 Android 手机、平板和电子笔记设备的用户提供文件浏览与双向传输。典型任务包括向设备批量导入电子书、导出笔记与图片、整理设备目录，以及处理中断后重新复制产生的同名文件。

核心成功标准：用户能够识别连接状态、明确选择存储与目标目录、完整传输所选文件，并区分成功、跳过、失败和取消；复制结果不能只凭进度条判断，验收需核对文件清单和下载后的内容。

### 1.1 用户与场景

| 用户 | 场景 | 主要诉求 |
| --- | --- | --- |
| 电子书/笔记设备用户 | 一次导入多本书，导出多层笔记目录 | 多选不丢文件，中文路径可用，目录层级保留 |
| Android 用户 | 在 Mac 和内置存储/SD 卡间传输照片、视频 | 清楚显示存储空间、目标位置和传输状态 |
| 高频文件整理用户 | 批量复制、剪切、重命名、删除 | 双栏、快捷键、冲突处理、操作反馈 |
| 遇到连接占用的用户 | 相机服务占用 MTP 接口 | 明确解释状态，提供手动修复入口和重试结果 |

### 1.2 平台与边界

- 声明支持 macOS 14.0+、Apple Silicon 和 Intel；arm64、x86_64、universal 是构建目标，各平台实际兼容性须单独验收。
- Android 设备通过可传输数据的 USB 线连接，并开启文件传输/MTP 模式；不以 USB 调试作为必要条件。
- 当前使用单一 LibMTP 后端，管理一个活动设备及其当前存储；不承诺多设备并行管理或跨存储直接移动。
- 主要交付是桌面应用与 DMG/ZIP；没有账号、云盘同步、无线传输、自动双向同步或设备端安装要求。
- 不承诺断点续传、内容去重、传输中即时中断底层文件读写、自动重试失败文件或重启后恢复队列。

## 2. 信息架构与主流程

### 2.1 页面构成

主窗口包含设备状态/文件操作工具栏、存储选择、文件面板、可选本地侧边栏、传输进度区与底部状态区。默认双栏；单栏模式聚焦 MTP 面板，仍可通过 Finder 拖入或粘贴上传。双栏支持交换本地与设备位置。

本地侧边栏提供常用目录与已挂载卷。文件面板包含路径导航、前进/后退/上级、筛选、视图与排序、选择和上下文菜单。独立窗口包含偏好设置、帮助、关于；弹窗包括删除确认、新建目录、冲突处理和错误提示。

### 2.2 主流程

1. 用户启动应用，应用展示本地目录与设备连接状态；自动连接默认开启。
2. 用户接入 MTP 设备，应用尝试连接，读取设备、能力、存储和根目录；连接受占用影响时展示修复入口。
3. 用户选择存储与目标目录，再通过拖放或复制/粘贴提交文件集合。
4. 应用展开目录并扫描冲突，用户选择逐项策略或应用于剩余冲突。
5. 应用执行文件队列，展示进度、速度和结果，允许在队列边界暂停、继续或取消。
6. 操作结束后刷新目标列表，用户核对文件。跨端剪切的源删除须符合下文的数据完整性要求。

## 3. 功能需求

优先级：P0 为核心连接、数据完整性及传输；P1 为常用管理与交互；P2 为辅助体验。下表的“有实现”仅表示代码路径存在；硬件、异常和发布环境结果仍需执行测试用例确认。

| 需求 ID | 优先级 | 功能 | 产品规则与验收标准 | 实现状态/边界 |
| --- | --- | --- | --- | --- |
| FR-01 | P0 | 设备检测与连接 | 启动和 USB 接入触发检测；成功展示设备名称、存储和根目录；非 MTP USB 设备不产生假连接；关闭自动连接后不自动发起连接 | 有 USBWatcher 和设备管理实现；自动检测开关覆盖启动扫描与插入事件 |
| FR-02 | P0 | 连接占用修复 | 被 macOS 相机服务占用时展示状态与“修复 MTP 连接”；仅用户点击后发起系统授权；执行中禁止重复点击；授权失败、取消或重连失败有明确结果 | 有手动释放服务及重连实现，不能承诺所有占用均可解除 |
| FR-03 | P0 | 存储与断连 | 展示设备返回的存储及容量；切换后浏览相应存储；拔出后清理旧设备状态；重新接入可再次浏览 | 多存储选择有实现；容量准确性及活动传输时切换须实测 |
| FR-04 | P1 | 目录浏览与导航 | 本地/MTP 均能进入目录、返回上级及前进/后退；根目录不能越界；刷新后数据与当前目录一致，失败可重试 | 有加载、空、错误及禁用状态；本地文件通过系统默认应用打开，MTP 文件不承诺直接预览 |
| FR-05 | P1 | 视图、排序与筛选 | 列表、小图标、大图标；名称/大小/类型/修改时间排序；目录优先；名称包含匹配不区分大小写；`.扩展名` 精确筛选文件，同时保留目录 | 本地图片/PDF 缩略图有实现；MTP 项目使用通用图标；隐藏文件开关分别控制两端 |

| FR-07 | P0 | 双向批量传输 | 本地上传/MTP 下载支持多个文件和递归目录；保留相对层级；每个文件有独立结果；中文、空格、特殊字符路径不应丢失或错写 | 非空目录递归有实现；空目录在扫描后被过滤，不能列为已支持，见 G-01 |
| FR-08 | P0 | 拖放完整性与目标解析 | 应用内多选拖动必须传输全部所选条目；Finder 多个 provider 均被处理；落入目录行时使用该目录，落入空白时使用当前目录；拖放不删除源文件 | 已修复完整文本被单文件 URL 抢先解析的问题；设备内拖放移动不作为已实现能力 |
| FR-09 | P0 | 复制、剪切、粘贴 | 本地到本地复制/移动；两端跨端复制/剪切；应用剪贴板为空时可读取 Finder 文件 URL；复制保留源；剪切只在可确认成功时删除源 | 跨端剪切失败/取消保留源有路径；跳过及空目录场景须按 G-02 验收 |

| FR-13 | P0 | 暂停、继续与取消 | 暂停后不开始后续文件，继续执行剩余项；取消后不再调度后续项，已完成文件保留，源文件不删除；不得把取消显示为整批成功 | 当前检查发生在队列文件边界；正在执行的 LibMTP 文件可能先完成；不保证立即停止 USB I/O |

| FR-15 | P1 | 布局与设置 | 单/双栏切换、双栏面板交换、侧边栏开关；隐藏文件设置分别持久化；字体 0.7–2.0 倍，步长 0.1，可重置为 1.0 | 布局、语言和偏好有持久化；不将所有视图/排序状态均承诺为跨重启保持 |

### 3.2 拖放格式规则

同一个拖动对象可能提供完整内部文件列表，以及只表示首项的标准文件 URL。接收端必须按以下顺序尝试解析，每个对象只采用第一个有效结果，避免重复入队：

1. `com.macmtp.file-items`：完整的本地或 MTP 条目列表。
2. `NSFilenamesPboardType`：路径数组。
3. `public.utf8-plain-text`：优先识别完整内部列表，其次兼容单文件 URL/绝对路径。
4. `public.file-url`：单文件回退。

格式读取失败或没有有效条目时继续尝试下一格式。多个 provider 分别解析后汇总；不要求其异步完成顺序等于拖动选择顺序，但要求目标文件集合准确。旧的进程内近期拖动缓存仍保留，必须测试外部无效拖动不会复用历史文件。

本地文件拖出 Finder 使用系统文件表示。MTP 拖出当前只为恰好一个非目录文件注册临时下载表示；多文件/目录到 Finder 不作为已支持范围，单文件仍列实机探索项，优先通过本地面板下载。

### 3.3 冲突决策表（跨端传输）

| 决策 | 同大小同名文件 | 不同大小同名文件 | 无冲突文件 |
| --- | --- | --- | --- |
| 覆盖 | 替换 | 替换 | 复制 |
| 跳过 | 保留目标 | 保留目标 | 复制 |
| 大小不同才覆盖 | 跳过 | 替换 | 复制 |
| 同大小跳过 | 跳过 | 替换 | 复制 |
| 取消 | 本次不开始传输 | 本次不开始传输 | 本次不开始传输 |

“同大小”不能证明“内容相同”。对于被中断的文件，重新提交后可按大小跳过已经完成的文件，但未完成文件仍需整文件重传。

### 3.4 状态与数据完整性规则

| 对象 | 状态/转换 | 验收关注 |
| --- | --- | --- |
| 设备 | 未连接 → 连接中 → 已连接；占用/失败 → 修复或重试；拔出 → 未连接 | 不残留旧设备文件列表与操作目标 |
| 文件面板 | 禁用、加载、已加载、空目录/无筛选结果、错误 | 区分真实空目录与筛选无结果，错误可重试 |
| 单文件 | 排队 → 预处理 → 传输 → 完成/失败；冲突可直接跳过 | 终态不可被迟到的进度回调改回传输中 |
| 批次 | 执行、暂停、完成、取消；部分文件失败必须在结果中体现 | 批次结束不等于每个文件成功；当前实现会短暂展示结束结果后清理 |

复制验收需核对相对路径、文件数、文件大小，并将设备文件下载回本地比较 SHA-256。空文件使用大小与内容哈希验收，不能因字节总量为零而漏项。对剪切，只有已经成功迁移且未跳过的内容才可删除；失败、取消、跳过均应保留相关源。该规则是验收目标，当前实现在 G-02 中存在风险。

## 4. 非功能需求与验收方式

| ID | 要求 | 验收方法 |
| --- | --- | --- |
| NFR-01 | 数据完整性：所选文件集合准确，复制不删源，剪切失败不丢源 | 清单、数量、大小、下载回读 SHA-256；异常后对比源目录快照 |
| NFR-02 | 可恢复性：断连/失败不应留下“成功”的误导状态，重连后可新建任务 | 传输中拔线、重新连接、重新提交；不要求自动断点续传 |
| NFR-03 | 响应与性能：大文件、批量小文件及大目录操作保持可交互 | 记录机型、系统、线材、设备、文件集合、耗时、吞吐、CPU/内存与卡顿；当前无已批准的吞吐/延迟 SLA，不将任意速度作为通过阈值 |
| NFR-04 | 一致性：列表/图标、单/双栏、工具栏/快捷键/右键的操作目标一致 | 交叉操作矩阵及编辑焦点测试 |
| NFR-05 | 兼容性：系统、架构、设备能力和存储组合可追踪 | 按测试矩阵记录真实覆盖；未测组合不能记为通过 |
| NFR-06 | 本地化与可用性：中英菜单/弹窗一致，长路径可辨认，缩放后关键操作可达 | 中文/英文、深浅色、最小窗口和字体边界检查 |
| NFR-07 | 诊断性：失败可定位到操作和文件，不依赖通知权限才能得知结果 | 核对 UI 状态与本地日志；日志为诊断信息，不作为唯一成功证据 |

## 5. 待验收差异与后续决策

以下由源码审阅识别，不是本次已执行实机测试后的缺陷结论。测试用例以期望的产品行为判定，不把现有风险写成正确行为。

| ID | 观察与影响 | 当前处理/后续验收 |
| --- | --- | --- |
| G-01 | 目录扫描记录了目录，但队列只保留文件，仅按文件目标创建父目录；空目录可能丢失 | 对空目录和混合目录验收；未修复前不宣称完整保留空目录 |
| G-02 | 跨端剪切仅以“无 failed 项”判断整组源删除，未排除 skipped 项；空目录同样可能遗漏 | P0：跳过/部分成功时不得删除未迁移源，必须实机验证并修正后才能通过 |
| G-03 | 本地粘贴的“同大小跳过”当前对所有冲突直接跳过；本地到本地拖动直接复制，未走统一冲突弹窗 | 分别验证入口差异，统一策略前不能用跨端规则推断本地行为 |
| G-04 | 新传输遇到非终态批次会报忙，但外层错误路径可能取消活动批次 | P0：重复提交不能破坏已有任务；单列异常用例 |
| G-05 | 部分新建、重命名、删除失败只记日志或忽略错误 | 验收要求可见反馈；未满足记缺陷，不能仅凭 UI 没崩溃通过 |
| G-06 | 近期拖动缓存只按时间兜底，缺少对当前拖动对象的强关联 | 外部无效拖动不得引入上次拖动文件；单列回归 |
| G-07 | 语言切换会重启；操作期间切换存储/退出的保护没有形成统一规则 | 验收目标是源数据保留、目标不串存储、无假成功；如未实现保护则记录缺陷 |
| G-08 | 旧 README 仍称设备内复制/移动不支持，MTP 到 Finder 尚未实现；旧验证文档仍提后端切换 | 本 PRD 以当前代码为准：前者为设备能力相关实现，Finder 单文件为待实机验证；当前无后端选择设置 |
| G-09 | 隐私相关默认值在多个入口不完全一致；当前依赖使用 SentryStub | 以首次运行实际结果记录默认值，不宣称已发送遥测；设置变化仍须验证持久化 |

## 6. 需求追踪与交付标准

所有 FR/NFR 的用例映射见 [测试用例的覆盖矩阵](../testing/TEST_CASES.md#8-需求覆盖矩阵)。交付时应记录安装包版本/哈希、源码提交及未提交补丁、系统/架构、设备及存储、测试状态和证据。

发布至少满足：P0 用例全部通过；数据丢失、误删、错目标、漏传、假成功问题无未解决项；已声明发布的系统/架构有安装与启动证据；未验证的设备能力和可选功能明确标记。文档中的需求/用例建立不代替实际测试执行。
