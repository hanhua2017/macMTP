## 1. 执行约定

- P0：阻断核心链路或影响数据完整性；P1：常用功能；P2：辅助体验。
- 状态使用“未执行、通过、失败、阻塞、不适用”。缺少设备/环境记阻塞；设备确实不具备可选能力且提示符合要求时，可将能力正向场景记不适用，负向场景仍需执行。
- 每条手工用例按其 ID 单独记录结果；表中一个步骤含多种参数时分别执行并记录子项，不能只测一种后整项通过。
- 用例预期为产品验收目标。涉及 PRD 的 G-01～G-09 时，应如实记缺陷，不能因为代码当前如此就判通过。
- 默认在隔离的测试目录进行复制、覆盖和删除，确认源/目标快照后操作；完成后按第 7 节清理。

## 2. 环境与数据准备

### 2.1 环境矩阵

| 环境标识 | 条件 | 覆盖要求 |
| --- | --- | --- |
| E0 | 无 MTP 设备的 Mac；支持本地目录及 Finder 操作 | 启动、本地管理、无设备状态 |
| E1 | Mac + 一台可读写 MTP 设备 + 一个当前存储 + 数据线 | 全部核心双向链路；记录设备型号、系统和固件 |
| E2 | E1 + 设备暴露第二存储（如 SD 卡） | 存储切换与目标隔离；无第二存储则阻塞相应场景 |
| E3 | E1 + 会被 macOS 相机服务占用的连接状态 | 占用识别、修复授权及重连 |
| E4 | 具备 CopyObject/MoveObject 的设备，以及不具备相应能力的设备或可控替身 | 设备内复制/移动正反向；替身不能代替真机成功证据 |
| E5 | 可控制剩余空间、只读/访问受限目录或受限设备存储 | 写入失败、容量不足和权限错误 |
| E6 | 声明支持的系统与架构组合、无构建依赖的干净测试机 | macOS 14 最低版本与当前版本；arm64/x86_64；发布 universal 的两个架构切片分别启动 |

语言至少覆盖简体中文、英文、跟随系统；外观覆盖浅色/深色；UI 至少覆盖双栏正常布局、双栏交换、单栏，列表/小图标/大图标。核心上传/下载至少在一套真实设备环境通过；不能把一次 arm64 测试推断为 Intel 或最低系统版本通过。

### 2.2 统一测试目录与数据

本地源记为 L，设备测试根记为 M，本地回读根记为 R。建议 L=`~/Downloads/macmtp-test-source`、M=`/macmtp-test-device`、R=`~/Downloads/macmtp-test-return`。每轮创建独立目标子目录，避免历史冲突污染结果。以下名称仅为建议，执行记录必须写实际路径。

| 数据标识 | 内容 | 用途 |
| --- | --- | --- |
| D1 | `one.txt`（1 KiB）、`two.pdf`（2 KiB，仅作二进制传输样本）、`三号 文件.epub`（3 KiB） | 多选、混合扩展名、中文空格、首项漏传回归 |
| D2 | `tree/level1/a.txt`、`tree/level1/level2/a.txt`、`tree/b.txt`、`tree/empty-child/` | 递归、重复文件名、层级与嵌套空目录 |
| D3 | `empty-dir/`、`zero.bin`（0 B）、`.hidden.txt`、`.hidden-dir/inside.txt` | 空目录、空文件和隐藏项 |
| D4 | 同名三组：目标不存在、同名同大小但内容不同、同名不同大小 | 冲突策略；同大小不等于内容相同 |
| D5 | 合法路径：中文、空格、emoji、冒号、长名称；本地另备含换行名（能力探索） | 编码及内部文本格式边界；设备拒绝非法名称时应提示而非静默丢项 |
| D6 | 100 个不同内容的小文件；实际大于 4 GiB 的单文件；足以观察暂停的多文件集合 | 批量、长传输、64 位大小、异常时机 |
| D7 | 源文件不可读、目标无写权限、目标剩余空间不足、传输前源被移走 | 失败与恢复；每个条件分别执行 |
| D8 | 一张有效 PNG/JPEG、一份有效多页 PDF、一个未知扩展名文件 | 缩略图和默认图标；不要用 D1 的占位二进制验证 PDF 预览 |

下面的可选命令只生成小型基础样本，不生成 D4 冲突目标、D5 全部边界、D6 大文件或 D7 异常条件。目录已存在时停止，防止覆盖历史数据。

```bash
python3 - <<'PY'
from pathlib import Path

root = Path.home() / "Downloads/macmtp-test-source"
root.mkdir(exist_ok=False)
files = {
    "one.txt": b"A" * 1024,
    "two.pdf": b"B" * 2048,
    "三号 文件.epub": b"C" * 3072,
    "tree/level1/a.txt": b"nested-one",
    "tree/level1/level2/a.txt": b"nested-two",
    "tree/b.txt": b"root-child",
    "zero.bin": b"",
    ".hidden.txt": b"hidden-file",
    ".hidden-dir/inside.txt": b"hidden-child",
}
for relative, content in files.items():
    target = root / relative
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_bytes(content)
for relative in ["empty-dir", "tree/empty-child"]:
    (root / relative).mkdir(parents=True, exist_ok=True)
print(root)
PY
```

### 2.3 统一判定方法

记“完整性核对”为：比较相对路径集合、目录集合、文件数、每个文件大小和 SHA-256。设备侧文件应下载回全新的 R 目录再比对，下载时避免与旧回读文件混合。上传不能仅凭应用本地队列成功就判定通过；大文件记录实际大小，不以稀疏占位文件证明真实大数据传输能力。时间戳不作为字节完整性证据。

本地可按以下命令输出清单。对 L 和 R 的对应根分别运行并保存输出；空目录也会记录。复制、跳过、失败、取消、剪切后另核对源目录快照。

```bash
python3 - "$HOME/Downloads/macmtp-test-source" <<'PY'
from pathlib import Path
import hashlib
import json
import sys

root = Path(sys.argv[1])
for path in sorted(root.rglob("*")):
    relative = str(path.relative_to(root))
    if path.is_dir():
        print(json.dumps({"path": relative, "type": "directory"}, ensure_ascii=False))
    elif path.is_file():
        digest = hashlib.sha256()
        with path.open("rb") as stream:
            for chunk in iter(lambda: stream.read(1024 * 1024), b""):
                digest.update(chunk)
        print(json.dumps({"path": relative, "size": path.stat().st_size,
                          "sha256": digest.hexdigest()}, ensure_ascii=False))
PY
```
